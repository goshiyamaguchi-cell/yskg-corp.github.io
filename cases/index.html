CASE 01 IT企業 経営支援

組織再編後に「役割・KPI・会議体・評価」が追いついていなかった会社

組織図は新しくなったが、予算管理・評価・会議の運用は旧組織のまま。KGI/KPI、部門の成果責任、経営会議、評価制度をひとつのプロジェクトとしてつなぎ直した。

課題

事業の成長に合わせて機能別組織へ再編したものの、各部門が何に責任を持ち、どの数字を見て、どこで判断するかは旧来のままでした。中期の成長目標と現場の動きがつながっておらず、マネージャー層は自分で案件をこなす業務に偏っていました。

YSKGの考え方

組織図を変えただけでは実態は変わりません。「部署を増やす」より先に、成果責任と意思決定の単位を見直し、それを指標と会議体に接続する必要があると考えました。

実施したこと

  • 中期の目標を全社KGI → 部門KPI → 役割・責任 → 会議体の順に分解し、「何を見て、誰が判断し、どこで修正するか」を整理
  • 候補となる指標に実数を入れてシミュレーションし、部門が行動を変えられる指標だけに絞り込み
  • 経営会議・部門会議で扱う内容（KPI進捗／部門横断課題／経営判断事項）を分け、会議ごとの役割を再設計
  • 役職ごとにKGIとKPIの比重を変える評価設計を検討し、戦略テーマには明示的なウェイトを設定
  • 各定例で「今日決めること」「次回までの宿題」を確定し、発表日から逆算して意思決定を進行

変化・現在の状態

中期計画が「年に一度見る資料」から、経営会議で継続的に更新する仕組みへ変わりました。組織再編を、運用設計まで含めてやり直した事例です。

CASE 02 設備・工事会社 経営支援・ビジネスコーチング

売上目標はあるが、達成に何が足りないかが分解されていなかった会社

中長期の売上目標を「不足している経営資源」に翻訳し、社長依存からの脱却と次世代経営者の育成を、計画づくりそのものを通じて進めた。

課題

中長期の売上目標は掲げられていましたが、その数字を実現するために何が足りないのかが整理されていませんでした。また社長自身が営業・見積・重要案件の判断に深く関わっており、成長するほど社長の時間がボトルネックになる構造がありました。

YSKGの考え方

計画書を完成させることより、最初に手を打つ領域と着手時期を決めることが重要です。また権限委譲は精神論ではなく、役割・判断基準・人材育成の設計として進めるべきだと考えました。

実施したこと

  • 目標と現在地の差を、営業・見積、現場責任者、協力会社、設備、資金、管理体制などの資源不足に置き換えて整理
  • 各資源を「社内でつくる／外部から取り込む／外部に出す」で手当てする方法を検討し、優先順位と着手時期を決定
  • 売上だけでなく案件数・責任者数などを年次マイルストーンに設定
  • 社長の仕事を「社長にしか出せない価値」へ移すため、見積の分担・外部化、現場責任者の育成、判断基準の明文化を検討
  • 経営研修ではなく、実際の中期計画づくりを題材に、資源配分と意思決定を経営者自身に行ってもらう育成プログラムとして伴走

変化・現在の状態

中期計画が、具体的な経営課題の一覧として使える状態になりました。経営人材は知識の量ではなく、資源配分と意思決定を自分で行う経験で育つことが確認できた事例です。

CASE 03 クリエイティブ・制作会社 経営支援

部門をまたぐ案件で、責任の所在と承認のタイミングが曖昧だった会社

問い合わせから振り返りまでを7つのフェーズに分け、5つのレーンで部門間の受け渡しと決裁ポイントを一枚の業務フローに設計した。

課題

問い合わせ、提案、契約、制作、納品、請求、振り返りまで複数の部門が関与していましたが、部門ごとの手順は分かっていても受け渡しの全体像が見えず、誰がボールを持っているのか、どこで承認が必要なのかが曖昧でした。

YSKGの考え方

業務フローは「作業一覧」ではなく、部門間の受け渡しと判断ポイントを管理する仕組みとして設計すべきだと考えました。

実施したこと

  • 業務を7つのフェーズに分解
  • 営業・企画・制作・管理・判断承認の5レーンでスイムレーン図を作成
  • 各フェーズで誰がボールを持つか、どこで承認（GATE）が必要か、どこで引き継ぎミスが起こりやすいかを可視化
  • フェーズ → タスク → 役割 → 承認ポイントの階層で詳細化シートを整備

変化・現在の状態

部門横断の案件を一枚で確認できるようになり、業務フローを属人的な手順書ではなく、現場で回る仕組みとして整備した事例です。

CASE 04 メーカー 組織人事コンサルティング

評価基準の曖昧さと、管理職の責任と報酬の逆転が同時に起きていた会社

評価制度だけを直さず、役割等級・成果/行動評価・報酬レンジの3つを一体で再設計し、個人別シミュレーションと移行措置まで検討した。

課題

評価基準の曖昧さ、複雑なインセンティブ、年功的な処遇、管理職の責任と報酬の逆転といった課題が同時に発生していました。

YSKGの考え方

「何を担い、どう成果を出せば、どう報われるか」が一本につながっていなければ、評価制度だけを直しても納得感は生まれません。等級・評価・報酬を同時に設計する必要があると考えました。

実施したこと

  • 役割の大きさに応じた役割等級を設計
  • 成果評価とバリュー（行動）評価を分けて設計
  • 等級ごとの給与レンジを設定し、等級・評価・報酬を接続
  • 制度移行時に不利益が大きくならないよう、個人別シミュレーションと移行措置を同時に検討

変化・現在の状態

「何を担い、どう成果を出せば、どう報われるか」が分かる構造へ再設計しました。人事制度改定を、制度設計と移行設計をセットで進めた事例です。

CASE 05 技術系企業 組織人事コンサルティング・ビジネスコーチング

研修を受けても「受けて終わり」になっていた会社

研修を育成の手段の一つに位置づけ直し、育成目標 → 研修/OJT → 1on1でのフォロー → 360度フィードバックを一つのサイクルとして設計した。

課題

外部研修を受講させても現場で使われたかを追えておらず、評価面談以外に部下の成長やキャリアについて定期的に対話する仕組みもほとんどありませんでした。

YSKGの考え方

管理職の役割を「評価者」で終わらせず、「育成の運用者」まで拡張する必要があります。1on1・360度フィードバック・育成目標を別々の施策にせず、一つのサイクルにすることが重要だと考えました。

実施したこと

  • 管理職の役割として、目標設定だけでなく1on1での進捗確認・状態把握・軌道修正までを明確化
  • 育成目標を設定し、その達成手段として研修・OJTを配置
  • 1on1で実践状況をフォローし、360度フィードバック等で変化を確認する流れを設計
  • 既存の評価シートやExcelを活用し、現場負荷を増やしすぎない運用を提案

変化・現在の状態

管理職要件を抽象的な「部下育成力」ではなく、実際に行う行動へ分解し、単発の研修から継続する育成サイクルへ変えた事例です。

CASE 06 IT企業 組織人事コンサルティング

エンジニアの離職率が高く、退職理由の集計では原因がつかめなかった会社

直属上司以外のサポート担当者が定期的に面談する仕組みを設け、在籍中に本音が出る接点を設計。離職率の低下につながった。

課題

エンジニアの離職率の高さが課題でしたが、退職面談で理由を集計しても、在籍中の不満や困りごとを早い段階で拾えていませんでした。マネージャー層はプレイング業務に偏り、部下の状態把握まで手が回らない状態でした。

YSKGの考え方

離職を個人の適性や採用ミスだけで説明せず、「離職兆候を誰が、どの頻度で、どの立場から拾うか」を設計することが重要だと考えました。

実施したこと

  • 直属上司（評価者）とは別に、サポート役の担当者がエンジニアと定期的に面談する仕組みを設計
  • 仕事の状況、不満、困っていることを、評価と切り離した立場で日常的に拾える接点を整備
  • 管理職が「自分で案件をこなす」以外のマネジメントに時間を使える前提として、部門の成果責任・KPI・会議体を整理

変化・現在の状態

このケースでは離職率の低下につながりました。ポイントは1on1の導入そのものではなく、本音が出る接点を誰がどう持つかを設計したことです。

CASE 07 広告代理店 ビジネスコーチング

経営者に判断材料の準備まで集中し、重要な判断が後回しになっていた会社

実際の事業計画や経営会議を題材に、経営者が決めることと管理担当者が整えることを分け、経営者自身が判断する場として育成プログラムを設計した。

課題

方針を決めることと、判断材料を用意することの両方が経営者に集中し、数字の確認や資料の作成に時間を使って、重要な判断が後回しになる構造がありました。

YSKGの考え方

知識の説明だけに時間を使わず、本人の会社の判断へ戻す設計が必要です。経営者が任せたいことを先に言葉にし、領域ごとに分担を置く構成にしました。

実施したこと

  • 事業計画・人事制度・経営会議の領域ごとに、経営者が担う役割と管理担当者が担う役割を整理するワークを設計
  • 目指す状態→必要な事業規模→現状との差→資源の手当て→年次目標→実行計画→リスク→損益計画の順に検討する事業計画の構成を用意
  • 幹部が決めてほしいことを議案として持ち込み、経営者が「決定／追加確認の期限／担当者に任せる」で返答する会議の進め方を提示
  • 説明する部分と参加者が記入する部分を分け、担当・次の行動・確認日をその場で決める時間を確保

変化・現在の状態

支援資料から確認できる範囲は、経営者の判断と担当者の準備を分けた育成の設計です。議案数の増加などの結果は確認していません。
